# a11y

`@meld-ts/core/a11y` 让 JSX 里的 `role`、`aria-*`、`tabIndex` 都通过 `a11y()` / `a11y.aria()` 写出，写错了在编译时报错。

## 为什么

`a11y()` 的结果是 spread 进 JSX 的，而 jsx-a11y 这类 lint 只检查 JSX 里字面写出来的 `role=`、`aria-*`，看不到 spread。所以改用 `a11y()` 以后，原来由 lint 做的检查交给类型来做：`a11y(role, props)` 按所选 lint 的规则表约束「必须有什么、允许有什么」。

规则表是 `bun run a11y:sync` 按各个 lint 的**默认规则**生成的，不读项目自己的 lint 配置。

## 接入

每个项目只在一个文件里创建实例：

```ts
// src/a11y.ts：唯一调用 createA11y 的地方
import { createA11y } from '@meld-ts/core/a11y';

export const a11y = createA11y({ lint: 'biome' });
```

项目同时跑多种 lint，就把它们**全部列出**：

```ts
export const a11y = createA11y({ lint: ['eslint', 'biome'] });
```

没有哪一张表是最严的。比如 eslint 要求 `combobox` 带 `controls`，biome 不要求；biome 要求可聚焦的 `separator` 带 `valuenow`，eslint 不要求。只绑一种，另一种的必填属性就会漏掉，而 lint 又看不到 spread，没有任何东西能拦住。列多个时，必填取并集，允许取交集。

`output` 选 `'react'`（默认）或 `'html'`：html 会把布尔和数字转成字符串（`aria-checked="true"`、`tabindex="0"`）。

开了 `isolatedDeclarations` 的项目，要用 `A11yOf` 标注类型：

```ts
const options = { lint: 'biome' } as const; // 这里不能加 satisfies，会报 TS9010
export const a11y: A11yOf<typeof options> = createA11y(options);
```

### 两个入口

| 入口 | 用途 | 输出 |
|------|------|------|
| `a11y(role, {...})` | 自定义 role（switch、img…） | `{ role, ...aria-* }`，带 `focusable` 时加 `tabIndex` |
| `a11y.aria({...})` | 原生元素补 aria 状态 | `{ ...aria-* }`，不带 `role` |

输入的键是去掉 `aria-` 前缀的小写名（`checked`、`labelledby`、`valuenow`）。

### 用项目自己的 lint 配置

内置表按默认规则生成。项目改过 lint 规则，就在项目根目录跑探针：

```bash
bunx --package @meld-ts/core meld-ts a11y probe
```

它会探测项目里装了哪些 lint，写出 `a11y-lints.generated.d.ts`，通过 `A11yLintOverrides` 覆盖内置表。

- 这个命令要用 Bun 跑，Node 跑不了。
- 生成文件的第一行 `export {};` 不能删。
- 探针只写出探测到的表，不会替你合并；跑了几种 lint，`createA11y` 里就列几种。

## 规则

下面 5 条，用 a11y 的项目抄进自己的 `AGENTS.md`：

1. 能用原生元素就用原生元素（button、a、input、select、dialog…）。
2. 原生元素补状态用 `a11y.aria({...})`，不手写 `aria-*`，也不对原生元素用 `a11y(role, ...)`。
3. 自定义 role 一律用 `a11y(role, {...})`，不手写 `role=` 和 `aria-*`。
4. 要可聚焦就传 `focusable: true`，不手写 `tabIndex`。唯一例外：只能用脚本聚焦的元素，手写 `tabIndex={-1}`。
5. 统一从 `src/a11y.ts` 导入 `a11y`，`createA11y` 只在这个文件里调。项目同时跑多种 lint，`lint` 里要全部列出。

## CI 检查

「不手写」可以用 grep 挂进 CI，排除接入文件：

```bash
rg --pcre2 '\b(role|aria-[a-z]+)\s*=(?!=)|\btabIndex\s*=\s*\{(?!\s*-1\s*\})|\btabIndex\s*=\s*["'\'']|\btabindex\s*=\s*["'\'']' \
  --glob '*.{tsx,jsx}' \
  --glob '!src/a11y.ts'
```

- 能抓到 `role="x"`、`role={var}`、`tabIndex={0}`、`tabIndex="0"`、`tabindex="0"` 等写法。只放过字面的 `tabIndex={-1}`（规则 4 的例外）。
- 会误报普通代码里的 `role = ...` 赋值，以及 `data-role`、`data-aria-label` 这类属性。宁可拦下来人工看，按需加排除。
- 先拼对象再 spread 的写法抓不到，靠上面的规则兜底。
- rg 返回 2 时是 rg 自己出错（正则坏了、没装 PCRE2），不要当成通过。本仓库的写法见 `.github/workflows/pr-check.yml`。

## 已知上游缺口

`aria-colindextext`、`aria-rowindextext` 在 React 19 的类型里有，但 aria-query 5.3.2 没收录，jsx-a11y 也把它们当无效属性。所以输入键里没有这两个，不要手工加。

确实要用时，spread 一个普通对象，role 照样走 `a11y()`：

```tsx
const extra = { 'aria-colindextext': 'Total', 'aria-rowindextext': 'Q3' };

<div {...a11y('gridcell', { colindex: 3 })} {...extra} />;
```

等 aria-query 收录后，`a11y:sync` 会自动带进来，到时候删掉这个写法。

## 维护（本仓库）

设计见 `docs/requirements/a11y-design.md`，进度见 `docs/requirements/a11y-roadmap.md`。

**生成文件。** `src/a11y/aria.generated.ts`、`src/a11y/lints/_*.ts`、`bin/a11y-probe/*.generated.ts` 都是生成的，文件头写着「生成文件，勿手改」，lint 版本也记在文件头里。要改就改 `scripts/a11y-sync.ts`，再重新生成。

| 命令 | 做什么 | 什么时候跑 |
|------|--------|------------|
| `bun run a11y:sync` | 在 `.cache/a11y-lab` 装最新的 lint，重新生成上面那些文件。约 2–4 分钟 | 改生成脚本、或 lint 出新版时 |
| `bun run test:a11y-lint` | 把 `a11y()` 的输出展开成字面属性交给 lint，要求零报错；再逐个删掉必填属性，要求 lint 报错。要先有 lab | 改了规则表或生成脚本后；发版前手工跑 |
| `bun run test:a11y-build` | 构建 dist，验证 `A11yLintOverrides` 覆盖在打包后的 d.ts 上仍然生效 | `version-bump.yml` 发版时自动跑 |

**发版前**手工跑两件事：`bun run test:a11y-lint`，以及漂移检查：

```bash
bun run a11y:sync && git diff --stat src/a11y/
```

有 diff，说明 lint 出了新版或者规则变了。

## 决定一：`types.test.ts` 的类型测试保持 `describe.skip`（round 5 后 27 个）

四个 `describe.skip` 块（round 4 复审后为五个：input constraints /
output inference / multi-lint merge / lint selection / output mode，
共 27 个 test）里的断言全是**编译期断言**：
`Assert<Eq<…>>` 类型相等检查和 `@ts-expect-error` 指令，真正的门禁是
`bun run ts-check`——它们当前全部被 tsc 检查且通过。运行期没有可执行的语义。

测试体里调用的 `a11yBiome` / `a11yBoth` / `maybeFocus` 等都是
`declare const`，只有类型没有值绑定，bun test 真去执行必然
`ReferenceError`（Task 3 实测：去掉 skip 后 15 个用例全部
`a11yBiome is not defined`）。`describe.skip` 让 bun test 只登记不执行，
27 个 skip 与最终输出完全对应；备选方案（运行时 stub / `as unknown as`）
会引入假运行时，被否。

## 决定二：`{}` → `Record<never, never>`（3 处）

Biome `noBannedTypes` 禁用 `{}`（`src/a11y/types.ts` 的 `NameRequirement`
else 分支、`FocusAttr` 两个空分支）。没用 biome-ignore 压制，改写为
`Record<never, never>`，依据是先验证恒等再动手：

- `Eq<Record<never, never>, {}>` 为 `true`——`{[P in never]: never}` 归约
  到内建空对象类型，两者是**同一类型**（严格恒等，不只是互相可赋值）；
- 赋值性、weak type 检测、条件类型解析在实际使用的全部位置行为一致
  （探针验证，详见 Task 6 报告）；
- 已知唯一差异：裸交叉类型里 `{}` 会被 TS 丢弃、`Record<never, never>`
  保留——当前类型结构中没有裸交叉空类型的用法，不触发。

## 决定三：r4 断言分语境——附录 `true | undefined`，实现 `boolean | undefined`

设计稿附录 A use.ts 的 r4 断言 `Eq<(typeof r4)['aria-expanded'], true | undefined>`
本来是对的，round 4 把它改成 `boolean | undefined`、并认定「附录写宽了」，是拿
实现测试的结论套了附录。两边的语境不同：实现测试（`types.test.ts`）里
`maybeBool` 是 `declare const`，无初始化器、不发生控制流收窄，react 模式对
`boolean | undefined` 输入的推导就是 `boolean | undefined`，实现侧断言正确、
保持不动；附录里 `onOpt` 是带初始化器的 `const`（`const onOpt: boolean |
undefined = ... ? true : undefined`），控制流先把它收窄成 `true | undefined`，
`a11y.aria({ expanded: onOpt, ... })` 推出的就是 `true | undefined`。round 5
已把附录改回 `true | undefined`（见设计稿 §12.3），抽出附录两个文件按头部
tsconfig 用仓库锁定的 tsc 5.9.3 复测，退出码 0；round 4 的「附录过于乐观」
说法作废。

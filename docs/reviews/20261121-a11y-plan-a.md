## 决定一：`types.test.ts` 的 16 个类型测试保持 `describe.skip`

三个 `describe.skip` 块（input constraints / output inference / multi-lint
merge，共 16 个 test）里的断言全是**编译期断言**：`Assert<Eq<…>>` 类型
相等检查和 `@ts-expect-error` 指令，真正的门禁是 `bun run ts-check`——
它们当前全部被 tsc 检查且通过。运行期没有可执行的语义。

测试体里调用的 `a11yBiome` / `a11yBoth` / `maybeFocus` 等都是
`declare const`，只有类型没有值绑定，bun test 真去执行必然
`ReferenceError`（Task 3 实测：去掉 skip 后 15 个用例全部
`a11yBiome is not defined`）。`describe.skip` 让 bun test 只登记不执行，
16 个 skip 与最终输出完全对应；备选方案（运行时 stub / `as unknown as`）
会引入假运行时，被否。

## 决定二：`{}` → `Record<never, never>`（3 处）

Biome `noBannedTypes` 禁用 `{}`（`src/a11y/types.ts` 的 `NameRequirement`
else 分支、`FocusAttr` 两个空分支）。没用 biome-ignore 压制，改写为
`Record<never, never>`，依据是先验证恒等再动手：

- `Eq<Record<never, never>, {}>` 为 `true`——`{[P in never]: never}` 归约
  到内建空对象类型，两者是**同一类型**（严格恒等，不只是互相可赋值）；
- 赋值性、weak type 检测、条件类型解析在实际使用的全部位置行为一致
  （探针验证，详见 Task 6 报告）；
- 已知唯一差异：裸交叉类型里 `{}` 会被 TS 丢弃、`Record<never, never>`
  保留——当前类型结构中没有裸交叉空类型的用法，不触发。

## 决定三：`r4['aria-expanded']` 断言为 `boolean | undefined`

设计稿附录 A（`docs/requirements/a11y-design.md:737`）断言
`Eq<(typeof r4)['aria-expanded'], true | undefined>`。实测 tsc 5.9.3
（锁定版本）下，react 模式对 `boolean | undefined` 输入的推导是
`boolean | undefined`：`OutValue<boolean, 'react'>` 原样透传，可选属性
访问类型补回 `undefined`，字面量 `true` 不会凭空出现（已用
`declare const` 对照探针证实 `boolean | undefined` 不可赋给
`true | undefined`）。按 brief 风险注记只改断言、不改实现——实现没有
问题，是附录该行写宽了。

## 改了什么

### 运行时行为（3 个 Important）

| 位置 | 问题 |
|---|---|
| `src/timer.ts` | `createTimer` 对象配置里的 `mode` 被静默忽略，`interval` 退化成 `timeout`——定时器语义完全错 |
| `src/events/index.ts` | `off(name, callback)` 不清理 `once` 标记，重新订阅的同一函数会意外只触发一次 |
| `src/async/retry.ts` | `timeout()` 里 fn 同步抛错不会变成 Promise rejection，调用方拿不到 Promise |

### 并发语义

- 并发 `emit` 时 `once` 回调会触发多次——修法是把「摘除 once」提到跑回调之前
- `pending()` 同步重入时 inflight 去重失效，`fn` 会跑多次
- `once` 回调在触发期间重入 `on()` 注册自己，被 emit 的 once 清理误删

### 探针与 CLI

- `detectLints` 对没有 `package.json` 的目录抛裸 ENOENT → 改成可读警告

## 跳过了什么

### `cloneObject` 遇不可 clone 值直接抛（不修）

`src/base/cloneObject.ts` 遇到函数等不可 clone 的值会抛错，而不是降级。

不修的理由：JSDoc 只承诺「structuredClone 不可用时降级到 JSON」，对不可 clone 值 fail-fast 是它本身的语义。改成静默降级会把函数字段悄悄丢掉，问题更大。

### `once` 的摘除时机文档与测试（当时跳过，后续已补）

修「并发 `emit` 时 `once` 触发多次」这一条时，把摘除动作从「跑完回调之后」提到了「跑回调之前」。行为变了，有三处文档还写「触发后」，也没有测试钉住新语义。

当时按「代码行为正确、文档和测试可以另补」跳过，维护者确认后补掉了，见下节。

## 补修的

### 文档

| 位置 | 改成 |
|---|---|
| `AGENTS.md:185` | `once` 回调在触发前就摘除，成功失败都只触发一次 |

| `src/events/index.ts:182` | `on(name, cb, true)` 等同于 `once()`——触发时先摘除、再执行回调 |

### 测试

原有测试已经覆盖「并发 emit 只触发一次」和「回调里用 `on` 重注册」，这次补了四条：

```ts
// once 回调在触发期间用 once 重新注册自己 → 3 次 emit 触发 3 次，之后不再触发
test('re-once during emit survives the cleanup and fires again later')

// 回调内重入 emit，内层快照里没有自己 → 只触发 1 次
test('re-entrant emit inside the callback does not fire it again')

// 快照执行期间 off 掉另一个监听器 → 本次仍执行，下次不再执行
test('off during emit does not affect the current snapshot')

// 快照执行期间 off 掉一个 once 监听器 → 本次仍执行一次，下次不再执行
test('off during emit still runs an already-cleared once listener once')
```

确认前两条真的钉住了语义：把摘除挪回 `Promise.all` 之后（故障注入），`src/events` 有 3 条测试转红，包括新增的这两条；恢复后 46 条全过。

后两条锁的是「快照语义」：emit 开始时取一次快照，触发期间对 `set` 的增删不影响本次执行。把 `snapshot.map` 改成实时集合 `[...set].map` 后，once 那条转红。
